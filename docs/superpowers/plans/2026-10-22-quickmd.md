# QuickMD Implementation Plan

**Goal:** Implement the supplied cross-platform local converter with installers, build pipelines and honest verification evidence.
**Architecture:** Shared sequential batch core; isolated conversion subprocess; separate OS adapters and installer ownership.
**Tech Stack:** Python 3.12, MarkItDown 0.1.9, PyInstaller 6.22.3, pytest, Inno Setup, Automator, Swift UserNotifications.
**Spec:** ../specs/2026-10-22-quickmd-design.md and ../../requirements.ko.md

## Global constraints
- Windows 10/11 x64; macOS 13+ Intel/Apple Silicon.
- Preserve source and existing outputs; local processing only; no background service.
- User installation without preinstalled Python; unsupported environments must not be reported as verified.

## Review focus
- Simultaneous publication must never replace a file or leave partial Markdown.
- Shell-metacharacter paths must arrive as data, including leading hyphens.
- A timed-out/crashed worker must release the conversion slot and preserve other results.
- Reinstall/uninstall must preserve unrelated files, PATH entries and user Markdown.
- Installer failure must retain a recoverable previous installation.

## Tasks
1. Core (`models.py`, `storage.py`, `validation.py`, `engine.py`, `conversion.py`): write regression tests for collision, invalid/empty, duplicate, four formats and worker bounds; observe missing implementation; implement and run pytest.
2. OS/CLI (`cli.py`, `diagnostics.py`, `queue.py`, `platforms/`): test argv/plist/registry contracts, queue draining and CLI exit codes; implement adapters, notification status and repair; run all tests.
3. Distribution (`packaging/`, `scripts/`, `.github/workflows/`): native PyInstaller build, Inno installer, macOS transactional install/uninstall, checksum downloads and optional signing. Run static validation and host package smoke tests.
4. Documentation and verification (`README.md`, `docs/`): Korean/English installation, security, upstream sources/licenses, manual OS matrix, release registration and exact observed results. Review implementation and run lint/types/full tests.

Execution: implement in this session, following the user's explicit instruction to begin actual implementation. Record progress in docs/PROGRESS.md. Do not publish, install into the user's live profile or claim remote CI execution.
